# Validation: stage space and docked controls

`e2e/mobileStage.test.ts` measures real SVG/Stage agreement for App, ordinary-node story, section-array story and Focus at 390x844, 768x1024, 1280x800, 1600x900 and 2560x1440, English/Spanish and light/dark. It enforces 60% App and 80% Focus/story drawing area, host containment, no horizontal/callout/subject overflow, real control reachability and no accidental nested narrow panel scrolling. A separate wide-font matrix checks complete translated labels and actual drawings.

Native controls, scene keyboard selection, story keys/pause, Focus Escape/return focus and opaque URL state are exercised after scrolling. Long HUD/rail content and mobile-desktop-mobile resize must preserve the sole Focus scroll owner and clear stale padding. NativeSelect tests cover controlled/uncontrolled/disabled/dynamic options, optgroup labels, actual ref and native identity, keyboard state, reset default action, long labels/wide fonts, listbox passthrough and a physically clipped-display negative.

`chartFallbackSizing.test.ts` proves hidden tables fit their deliberate host while retaining every cell, native table accessibility and aria-details. Removing sr-only restores automatic visible table layout and full data access. `focusChromeCoverage.test.ts` plants the same physical label-over-control defect in owner-direct and legacy metadata compositions, with clean controls before/after. Owning gate selftests remain required; the gate's overlap and cut-label conditions are unchanged.

CAOS_MOBILE_BASELINE_CSS supports a read-only released-CSS/candidate-DOM diagnostic, not an immutable baseline executable. Preserve exact red, source and output identities. Run package build, unit tests, SDD, full browser suite and gate selftests with external E TEMP/TMP/CAOS_TEMP_ROOT. A selected test cannot establish a complete suite. Actual SoftQP drawing/layout checks over external new-source drafts do not establish scientific correctness, installed-package or release acceptance.

The eight storyNavigation tests cover390/768px, EN/ES and normal/wide typography: six complete verbs in one horizontal row, direct-load selected-step reveal, Home and keyboard access through all offscreen links, page containment and a physical clipping negative.

The twelve focusDockDensity tests run the actual clean gate fixture across1280/1600/2560, EN/ES/themes, each with three cases and normal/wide fonts (72states). They require every control and final readout to fit, unchanged title/control fonts, no cut text or coverage, keyboard slider operation and the disabled native control. Optional CAOS_FOCUS_DOCK_BASELINE_FIXTURE serves the read-only exact compiled pre-density snapshot to reproduce its genuine red overflow.

`nativeSelectTransitions.test.ts` compares the same real node, selected options and FormData against ordinary native controls through size1/3 and multiple transitions, including user-held nondefault selections, controlled mode and native form reset. A separate hidden control applies inline display:block and checks zero native/wrapper/mirror rectangles and hit targets, restored associated-label focus/selection, and visible disabled state in popup/listbox/multiple modes.

`storyStageFooter.test.ts` uses an explicit synthetic grid instrument with a Stage in minmax(0,1fr) and an intrinsic explanation sibling. Across all five sizes, both languages/themes and normal/wide fonts, it requires the actual drawing to precede that sibling without overlap, both to fit the actual scene/Story owner, actual drawing share of80percent, desktop containment and reachable coupled controls. Actual product footer/label bounds require a separate developmental successor receipt; synthetic layout alone does not establish product or scientific acceptance.
